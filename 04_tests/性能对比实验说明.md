# 单体与微服务性能对比实验

## 实验设计

- 基线：Git 标签 `monolith-start` 中的单体 backend。
- 改造版：当前提交中的独立 `live-service`。
- 环境：同一个 GitHub Actions `ubuntu-latest` runner、同一个 MySQL 8 服务容器、同一套 Java 21 和压测脚本。
- 数据：两个隔离数据库使用相同结构和 100 条相同内容的直播间记录。
- 接口：直播间列表、直播间详情、点赞数查询。
- 负载：16 并发、每个接口每个版本重复 3 次、每次 30 秒。

## 指标

脚本记录请求总数、成功/失败数、吞吐量（RPS）、平均响应时间、P95 响应时间、错误率、进程平均 CPU 和峰值 RSS 内存。原始结果位于 Actions artifact 的 `performance-results.csv`，每个接口的原始请求耗时和进程采样文件也会保留。

## 执行入口

- 脚本：[`scripts/performance-compare.sh`](../scripts/performance-compare.sh)
- CI 工作流：`.github/workflows/live-service-ci.yml` 的 `Performance comparison` job。

## 最近验证结果

Actions run `33608439523`（commit `026ffc2`）已完成该实验，结果和原始采样位于 artifact `monolith-microservice-performance-comparison`。报告引用以 artifact 中的 CSV 为准，不手工填写模拟数字。

## 结果规则

实验必须以实际 Actions run 产物为准，不预填模拟数字。报告中应列出三次重复结果及均值/离散情况，并说明两个版本使用同机、同数据、同接口和同负载脚本。
