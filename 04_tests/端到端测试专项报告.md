# 端到端测试专项报告

## 1. 审核结论

本报告针对三条验收要求核对当前测试实现：真实执行、输入输出可追溯、完整操作链路和原始输入。

| 要求 | 当前结论 | 说明 |
| --- | --- | --- |
| 端到端测试必须是真实的 | 基本满足，但需区分故障注入 | 后端 E2E 和 SRS 浏览器用例访问真实运行服务；部分浏览器异常用例通过 Playwright 路由模拟故障，不能计作真实依赖故障测试 |
| 报告写清输入输出 | 已补齐自动化证据入口 | Playwright 保存每个用例的 `e2e-io.json`，同时生成 HTML/JSON 报告；Maven Surefire 报告上传。业务输入和输出断言见第 3 节 |
| 完整操作链路和原始输入 | 直播主链路满足 | 后端 E2E 和 SRS E2E 覆盖完整链路；原始请求体、请求头、WebSocket 帧和 FFmpeg 参数由源码及 `e2e-io.json` 留存 |

## 2. 什么算真实 E2E

真实 E2E 的判定标准是：测试进程通过 HTTP/WebSocket/浏览器访问已启动的应用服务，并经过真实路由、Controller、Service、数据库或 SRS，而不是直接调用 Java 方法或只验证 Mock 返回值。

### 真实链路

- `backend/src/test/java/com/example/demo/LiveE2ETest.java`：随机端口启动 Spring Boot，使用 Java `HttpClient` 和 `WebSocket`，CI 连接 MySQL 8。
- `live-service/src/test/java/com/example/live/LiveServiceE2ETest.java`：随机端口启动服务，使用外部 HTTP/WebSocket 客户端完成直播链路。
- `frontend/demo/e2e/live-ui.spec.js` 的 SRS 用例：真实启动后端、前端、SRS 和 FFmpeg，检查 HTTP-FLV 200 及浏览器 `video.currentTime` 增长。

### 故障注入，不冒充真实链路

以下用例明确是前端故障注入，用于验证降级 UI，不代表真实 SRS/网络故障：

- 详情接口异常：`page.route(...).abort()`。
- `pullUrl` 为空或清晰度变更：`page.route(...).fulfill()` 改写响应。
- WebSocket 未连接：`page.routeWebSocket(...).close()`。

这些用例仍然经过真实页面、组件和状态管理；报告中与 SRS 成功链路分开统计。

## 3. 直播主链路输入/输出

### 后端 E2E

源码：[backend LiveE2ETest.java](../backend/src/test/java/com/example/demo/LiveE2ETest.java)

| 步骤 | 原始输入 | 输出/断言 |
| --- | --- | --- |
| 创建房间 | `POST /api/live/rooms`，`X-User-Id: 1`，`{"title":"端到端测试直播间","categoryId":1,"coverUrl":""}` | `code=200`，取得动态 `roomId`，状态 `online` |
| 查询详情 | `GET /api/live/rooms/{roomId}` | `status=online`，`pullUrl` 和原画地址非空 |
| 建立观看连接 | `ws://127.0.0.1:{随机端口}/ws/live/{roomId}`，两个客户端 | 两个客户端都收到 `online_count` |
| 发送弹幕 | `{"type":"danmu","userId":1,"username":"测试用户","content":"主播晚上好","color":"#ffffff"}` | 另一客户端收到同内容 `danmu`，历史查询包含该内容 |
| 非法弹幕 | 空白内容和 300 个 `x` | 不新增弹幕，连接不关闭 |
| 发送点赞 | `{"type":"like","userId":1}`，随后重复 10 次 | 广播计数递增，数据库查询为初始值加 11 |
| 关闭房间 | `POST /api/live/rooms/{roomId}/close`，`X-User-Id: 1` | 状态变为 `offline` |
| 最终校验 | `GET /api/live/rooms/999999` | 返回业务 `code=404` |

### 浏览器 SRS E2E

源码：[live-ui.spec.js](../frontend/demo/e2e/live-ui.spec.js)

| 步骤 | 原始输入 | 输出/断言 |
| --- | --- | --- |
| 创建房间 | `POST /api/live/rooms`，标题 `Playwright 测试直播间`，分类 `1`，用户 `1` | 返回 `roomId` |
| 获取推流地址 | `GET /api/live/rooms/{roomId}` | 取得 `pushUrl` 和 stream key |
| 真实推流 | FFmpeg `testsrc=640x360:15fps` + `sine=440Hz`，输出 FLV 到 `pushUrl` | FLV 请求返回 HTTP 200 |
| 浏览器播放 | 打开 `/#/live/{roomId}` | `video.live-player` 存在且 `currentTime > 0.5` |

## 4. 报告和原始证据位置

Playwright 每个用例结束时生成并附加：

- `e2e-io.json`：浏览器侧 HTTP 请求/响应、失败请求、WebSocket 打开/发送/接收/关闭事件；敏感请求头会脱敏。
- `backend-live-e2e.json`、`live-service-e2e.json`：Java E2E 侧实际 HTTP 请求/响应和 WebSocket 发送/接收记录，位于 Maven `target/e2e-artifacts/`。
- `playwright-report/index.html`：HTML 可视化报告。
- `playwright-report/results.json`：机器可读结果。
- `test-results/`：失败时的 trace、截图和视频。

CI 工件：

- `backend-maven-test-reports`：后端 Surefire XML/TXT 报告和 Java E2E 原始 I/O JSON。
- `browser-e2e-reports-and-raw-io`：两组 Playwright HTML/JSON、原始 I/O、trace/截图/视频和后端/Vite 日志。

当前配置入口：

- [playwright.config.js](../frontend/demo/playwright.config.js)
- [reporting.js](../frontend/demo/e2e/reporting.js)
- [ci.yml](../.github/workflows/ci.yml)

## 5. 执行命令

```bash
cd frontend/demo
npx playwright test --grep-invert "SRS"
RUN_SRS_E2E=true npx playwright test --grep "SRS"
```

后端：

```bash
cd backend
./mvnw -B -Dtest=LiveE2ETest test
```

验收时应同时提交 HTML/JSON 报告和 `e2e-io.json`，不能只提交终端中的“passed”汇总。
