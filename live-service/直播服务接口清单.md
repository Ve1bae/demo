# 直播服务接口清单

> 服务前缀：`/api/live`  
> 当前实现：`live-service`，负责直播间生命周期、推拉流地址、弹幕、点赞、在线人数和 SRS 探活。

## 一、HTTP 接口

| 编号 | 方法 | 接口 | 主要用途 | 请求参数/请求体 | 返回结果 |
| --- | --- | --- | --- | --- | --- |
| LIVE-API-01 | `POST` | `/api/live/rooms` | 创建并开始一个直播间 | 请求头 `X-User-Id`；JSON：`title` 必填，`categoryId` 可选，`coverUrl` 可选 | `ApiResponse<LiveRoomView>`，包含直播间 ID、推流地址、播放地址和状态 |
| LIVE-API-02 | `GET` | `/api/live/rooms` | 分页查询在线直播间 | Query：`page` 默认 `1`，`pageSize` 默认 `12`，`categoryId` 可选 | `ApiResponse<PageResult<LiveRoomView>>` |
| LIVE-API-03 | `GET` | `/api/live/rooms/{roomId}` | 查询直播间详情和播放信息 | Path：`roomId` | `ApiResponse<LiveRoomView>` |
| LIVE-API-04 | `POST` | `/api/live/rooms/{roomId}/close` | 主播结束自己的直播 | 请求头 `X-User-Id`；Path：`roomId` | `ApiResponse<LiveRoomView>`，状态变为 `offline` |
| LIVE-API-05 | `GET` | `/api/live/rooms/{roomId}/danmus` | 查询直播间历史弹幕 | Path：`roomId`；Query：`limit` 默认 `50`，最大 `200` | `ApiResponse<List<LiveDanmuView>>` |
| LIVE-API-06 | `GET` | `/api/live/rooms/{roomId}/like` | 查询直播间累计点赞数 | Path：`roomId` | `ApiResponse<{likeCount: number}>` |
| LIVE-API-07 | `GET` | `/api/live/srs/health` | 检查 SRS 服务是否可用 | 无 | `ApiResponse<Map<String, Object>>` |

## 二、运维接口

课程要求流水线和现场演示能够进行健康检查，当前服务通过 Spring Boot Actuator 暴露以下接口：

| 编号 | 方法 | 接口 | 主要用途 | 返回结果 |
| --- | --- | --- | --- | --- |
| OPS-API-01 | `GET` | `/actuator/health` | Kubernetes 存活、就绪探针和流水线健康检查 | 服务健康状态，正常时包含 `UP` |
| OPS-API-02 | `GET` | `/actuator/info` | 查看服务基础信息 | 当前配置的信息项；未配置时内容可能为空 |

> `/actuator/health` 是运维接口，不单独算作直播业务用例；业务接口和业务用例测试仍按 LIVE-API 编号及项目用例清单执行。

## 三、创建直播间

请求：

```http
POST /api/live/rooms
X-User-Id: 10
Content-Type: application/json

{
  "title": "测试直播间",
  "categoryId": 1,
  "coverUrl": "https://example.com/cover.jpg"
}
```

`title` 不能为空，长度不超过 100；`coverUrl` 最长 500。创建成功后直播间状态为 `online`，同时生成唯一 `streamName`、`pushUrl` 和 `pullUrl`。

## 四、直播间详情返回字段

`LiveRoomView` 主要字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `roomId` | `Long` | 直播间 ID |
| `userId` | `Long` | 主播用户 ID；身份由网关/JWT 校验后传入 |
| `categoryId` | `Long` | 分类 ID，可为空 |
| `title` | `String` | 直播间标题 |
| `streamName` | `String` | SRS 流名称 |
| `pushUrl` | `String` | 主播端推流地址 |
| `pullUrl` | `String` | 默认播放地址，当前为 FLV 地址 |
| `qualityUrls` | `Map<String, String>` | 原画、720P、480P 播放地址 |
| `coverUrl` | `String` | 封面地址，可为空 |
| `status` | `String` | `online` 或 `offline` |
| `streamActive` | `Boolean` | SRS 探活结果；未开启探活时可为空 |
| `createdAt` | `LocalDateTime` | 创建时间 |

## 五、关闭直播间的权限规则

- `X-User-Id` 必须是正整数。
- 只有直播间所属主播才能关闭直播间。
- 直播间已经是 `offline` 时，返回业务错误“直播间已经结束”。

## 六、WebSocket 接口

### 1. 连接地址

```text
ws://<host>/ws/live/{roomId}
```

连接成功后，服务端会向当前房间广播在线人数，并向新连接发送当前点赞数。直播间不存在时连接会被关闭。

### 2. 客户端消息

发送弹幕：

```json
{
  "type": "danmu",
  "userId": 10,
  "username": "主播",
  "content": "晚上好",
  "color": "#ffffff"
}
```

发送点赞：

```json
{
  "type": "like",
  "userId": 11
}
```

规则：

- `userId` 必须为正整数。
- 弹幕内容不能为空，且不超过 255 字。
- `username` 为空时使用 `用户 {userId}`。
- `color` 为空时使用 `#ffffff`。
- 直播间不在线时，弹幕和点赞都会返回业务错误。

### 3. 服务端广播消息

| 消息类型 | 触发时机 | 主要字段 |
| --- | --- | --- |
| `online_count` | 用户连接或断开 | `type`、`count` |
| `danmu` | 弹幕保存成功 | `type`、`id`、`roomId`、`userId`、`username`、`content`、`color`、`sendTime` |
| `like` | 点赞成功或新用户连接 | `type`、`likeCount` |
| `error` | 消息格式错误、参数非法或业务操作失败 | `type`、`message` |

示例：

```json
{"type":"online_count","count":2}
```

```json
{"type":"like","likeCount":18}
```

## 七、错误处理约定

HTTP 接口统一使用 `ApiResponse` 返回；参数校验失败、直播间不存在、未开播、无权限等情况由全局异常处理器转换为业务错误响应。WebSocket 连接断开后由客户端负责提示用户并执行重连策略，服务端会清理连接并广播最新在线人数。

## 八、微服务边界

- 本服务只维护直播领域数据，不直接读取用户中心、分类服务或其他微服务的数据库。
- `X-User-Id` 应由网关/JWT 认证层注入，不能把客户端传入的用户身份当作认证凭据。
- 用户信息、分类名称等扩展信息由调用方或网关通过其他服务获取；直播服务只保存必要的 `userId` 和 `categoryId`。
