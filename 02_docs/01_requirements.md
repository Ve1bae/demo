# 需求说明与业务场景清单

## 1. 范围与角色

系统为视频点播与直播平台，当前仓库包含单体 backend、独立 live-service、Vue 前端、MySQL、MinIO 和 SRS。角色：游客、登录用户、主播、管理员/运维人员、外部 SRS 服务。

| REQ-02 | 用户浏览推荐视频、查看详情和播放历史 | 已实现，推荐接口已纳入 CI |

## 4. 用例说明（代表性用例）

### UC-05 创建直播间

- 触发条件：主播已获得用户 ID，提交非空标题。
- 前置条件：live-service、live-mysql 可用。
- 主成功流程：校验用户和标题 → 生成唯一 `streamName` → 写入 `live_room`（`online`）→ 返回 `pushUrl`、`pullUrl`、清晰度地址。
- 备选/异常：用户 ID 缺失或标题为空返回 400；数据库不可用返回服务错误；重复 streamName 不允许写入。
- 结果：房间记录可查询，状态为 `online`，可供后续推流验证。

### UC-06 观看与互动

- 触发条件：观众打开房间 WebSocket，并向 SRS 发布测试流。
- 前置条件：房间在线、SRS API 可达。
- 主成功流程：RTMP 推流 → SRS HTTP-FLV 输出 → 观众建立 WebSocket → 发送弹幕/点赞 → 其他连接收到广播 → 数据库记录可查询。
- 备选/异常：空弹幕、超长弹幕、未知消息类型、离线房间互动均返回明确错误且不改变计数。
- 结果：FLV 文件以 `FLV` 头开始并有数据，弹幕和点赞结果可追溯。

### UC-07 结束直播

- 触发条件：房主请求关闭自己的房间。
- 前置条件：房间状态为 `online`，请求带正确用户 ID。
- 主成功流程：校验归属 → 更新状态为 `offline` → 返回关闭后的房间。
- 备选/异常：非房主、缺少用户 ID、重复关闭均返回业务错误，原状态保持不变。
- 结果：离线房间不能继续发送弹幕或点赞。

### UC-08 自动部署

- 触发条件：向 `live-service` 分支 push。
- 主成功流程：测试 → 构建三镜像 → 创建 Kind → 配置 Secret/ConfigMap/PVC → 部署 MySQL、SRS、MinIO 和应用 → rollout → API/RTMP/FLV 验证。
- 失败处理：任一步失败立即停止后续发布；自动收集 Pod、Deployment、PVC 和容器日志并上传工件。
- 结果：GitHub Actions 成功运行并保留 run URL、提交 SHA 和测试报告。
