# 航音视频微服务版测试计划

## 1. 测试目标

验证 `microservice` 分支在三个业务微服务拆分后，仍能覆盖 UC-01 至 UC-10 的主成功流程、备选流程和异常流程，并满足课程任务书对单元测试、集成/API 测试、端到端测试、部署验证、云原生实验和性能对比的要求。

## 2. 测试范围

| 范围 | 被测对象 | 主要入口 |
| --- | --- | --- |
| 用户与账户 | 注册、登录、资料、关注、兴趣、观看历史 | `user-service/src/test/`、`scripts/run-user-service-e2e.ps1` |
| 视频与推荐 | 上传、管理、推荐、播放、评论、视频弹幕 | `video-service/src/test/`、`scripts/video-e2e.mjs`、`frontend/demo/e2e/` |
| 直播与互动 | 直播间、SRS 播放、直播弹幕、直播点赞 | `live-service/src/test/`、`scripts/uc07-e2e.mjs`、`frontend/demo/e2e/live-ui.spec.js` |
| 部署与运行 | Compose、健康检查、Kubernetes、HPA、故障降级 | `scripts/verify-k8s-microservices.ps1`、`scripts/hpa-load-test.ps1`、`scripts/fault-drill-microservices.ps1` |
| 性能 | 单体/微服务相同接口、数据和并发梯度对比 | `scripts/run-api-benchmark.ps1`、`performance/README.md` |

## 3. 测试层次与通过标准

| 层次 | 关注内容 | 通过标准 |
| --- | --- | --- |
| 单元测试 | 关键类、方法、业务规则、边界和异常分支 | 断言有效；三个服务 Maven 测试通过 |
| 集成/API 测试 | Controller、Service、Mapper、数据库和跨服务 HTTP 调用 | 主流程、备选流程和异常流程有响应断言 |
| 端到端测试 | 从 HTTP 或浏览器入口走完整业务场景 | UC-01 至 UC-10 有对应自动化回归；失败时退出码非 0 |
| 部署验证 | 镜像、Compose、Kubernetes、就绪/存活探针 | 服务 rollout 成功，网关、推荐和直播接口可访问 |
| 性能测试 | 吞吐量、平均/P95、错误率、CPU、内存 | 单体和微服务在同机同数据同参数下各运行至少 3 次 |

## 5. 测试环境与数据

- Java 21、Node.js 22、Maven 3.9、MySQL 8.4、Docker Compose、Kubernetes。
- 微服务通过 `docker-compose.microservices.yml` 启动；网关入口为 `http://127.0.0.1:8080`。
- 单体基线通过 `docker-compose.monolith-benchmark.yml` 隔离启动，入口为 `http://127.0.0.1:18080`。
- 测试数据使用仓库中的数据库初始化和 E2E seed 脚本；密码只通过环境变量或 CI Secret 注入。
- 每次测试记录分支、提交号、执行时间、命令、总数、通过数、失败数、错误数和原始输出。

## 6. 流水线门禁

`.github/workflows/uc03-microservices-cicd.yml` 的顺序为：三个服务 Maven 测试和 Compose 配置校验 -> Compose API/E2E 与浏览器 E2E -> push 时构建版本化镜像 -> Kind Kubernetes 部署 -> 网关健康检查。前置 job 失败时，后续 job 因 `needs` 不执行；测试命令返回非零退出码时不发布镜像、不部署。
