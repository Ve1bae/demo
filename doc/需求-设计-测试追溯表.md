# 《航音视频》需求、设计与测试追溯表

## 1. 目的与使用说明

本表建立《软件需求规格说明书》、 《软件概要设计说明书》、 《软件详细设计说明书》、实现单元与测试用例之间的双向追溯关系，用于中期检查、测试覆盖审查和后续变更影响分析。

- 主追溯键：`REQ`（需求）→ `UC`（用例）→ `DES`（概要设计）→ `DD`（详细设计）→ 实现单元/系统操作 → `TC`（测试）。
- 测试结果来源：`doc/4组测试报告.md` 第 8 章，以及各 UC 专项测试报告；结果口径为报告中记载的 2026-08-28 本地重测结果。
- “后端容器系统测试”指真实启动后端、MySQL、MinIO、SRS 等运行环境后，通过 HTTP/WebSocket 入口验证用例基本流程和扩展流程；组件级 MockMvc 集成测试不作为本表的重点验收依据。
- 用例中的登录/身份校验为公共前置能力，由 `DES-08`、`DD-01` 支撑；演示版本通过 `X-User-Id` 或请求体 `userId` 适配登录态。

## 6. 变更影响规则

1. 修改 `REQ` 的功能范围、验收条件或异常流程时，必须同步检查对应 `UC`、`DES`、`DD`、实现接口和本表中的全部 `TC`。
2. 修改系统操作（REST 路径、请求字段、WebSocket 消息类型、错误码）时，必须更新详细设计接口章节、对象级顺序图、单元测试和容器系统测试。
3. 修改基础设施端口、服务名、凭据变量或代理配置时，必须更新 `application.yml`、`docker-compose.yml`、CI 工作流、Kubernetes 配置和 REQ-07 对应验证记录。
4. 只有测试在目标环境中稳定通过，才可将本表的覆盖结论标记为“通过”；Flaky、失败、跳过和仅条件通过必须保留风险说明。
