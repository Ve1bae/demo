## 现场演示顺序

1. 展示 `docker compose ps` 和 `/gateway/health`，说明三个服务、三个数据库、MinIO、SRS 与网关的关系。
2. 打开首页展示 UC-03 推荐；切换登录用户后展示关注作者优先，并说明 video-service 通过 HTTP 获取用户偏好。
3. 进入视频详情，演示播放计数、评论、弹幕、点赞/收藏中的代表流程。
4. 展示 `kubectl get deployment,pods,hpa -n hangyin`，运行负载脚本并观察 video-service 副本从 1 增加到 3；展示 `evidence/hpa/20260903-031813/` 中停止负载后的 1 副本输出。
5. 停止 user-service，展示推荐降级为热度结果且直播列表不受影响；恢复服务后再次请求。
6. 展示微服务性能 CSV/Markdown。单体对比若仍未补齐，应主动说明原因，不展示伪造数据。

## 答辩前硬性检查

1. 不要把测试脚本存在写成测试已经通过。
2. 不要把 HPA YAML 存在写成已经发生扩容，必须保存负载期间和负载下降后的副本数输出。
3. 不要把故障降级代码存在写成故障演示完成，必须保存请求响应和服务日志。
4. 不要提交密码、Token、本地构建产物或 `target/`、`dist/`、Playwright 临时报告。
5. 当前 `microservice` 分支尚未 push；CI 运行记录只能在实际 push 后补充。
