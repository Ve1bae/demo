## 2. 测试依据与目标

测试依据为《软件工程基础实践》课程任务书、软件需求规格说明书中的 `REQ-02` 和 `UC-03`，以及 UC-03 系统级、组件级和对象级交互设计。

本轮测试目标如下：

1. 验证推荐服务中的筛选、打分、排序、分页和异常分支。
2. 验证 Controller 的参数绑定、请求头处理和响应格式。
3. 验证 Spring 容器、JDBC 仓储与数据库之间的集成。
4. 验证制成镜像后的服务能够连接真实 MySQL、通过健康检查并响应真实 HTTP 请求。
5. 验证用户从前端首页执行推荐浏览、筛选、登录推荐、空结果和进入播放页的完整流程。
6. 为流水线保留可判断的断言、原始输入和实际输出；任一测试失败时停止后续步骤。

## 3. 测试范围

### 3.1 已测试

- 游客读取公开视频。
- 登录用户携带 `X-User-Id` 后读取观看历史。
- 关注作者、兴趣标签和已观看视频对推荐分数的影响。
- 分类和关键词组合筛选。
- 推荐排序、分页、空结果和边界参数修正。
- 非数字页码、非数字用户标识等异常输入。
- 标签解析、视频播放地址和作者关注状态的响应字段补充。
- MySQL 建表、初始化数据、容器启动和健康检查。
- Docker 镜像中的服务启动及真实 HTTP API 调用。
- Chromium 通过 Vue 前端访问单体后端和临时 MySQL 的 Playwright 浏览器端到端流程。

### 3.2 本轮未测试

- 真实 user-service 的关注和兴趣接口契约。当前 user-service 尚未提供约定的偏好接口，服务默认降级为游客偏好。
- 前端或网关直接访问拆分后 `video-service:8083` 的浏览器端到端链路。当前 Playwright 结果属于单体后端链路，不能替代微服务网关 E2E。
- 视频播放、上传、转码和管理等其他组员负责的 video-service 接口。
- Kubernetes 部署、HPA、故障处理和性能对比。

## 11. CI 执行与失败阻断

现有 `.github/workflows/ci.yml` 已增加 `video-service-tests` 和 `uc03-browser-e2e` 两个独立作业，监听：

- `feature/video-service`
- `feature/video-service-*`
- 面向 `feature/video-service` 或 `main` 的 Pull Request

作业执行顺序：

```text
取代码
  -> 配置 Java 和 Node.js
  -> 运行 33 项 JUnit 测试
  -> 构建 video-service 镜像并启动 MySQL
  -> 运行 8 项真实 API 测试
  -> 保存 Surefire、API JSON 和容器日志
  -> 清理隔离环境
```

步骤使用默认的成功依赖关系。JUnit、镜像构建、容器启动或真实 API 断言任一步失败，后续正常步骤不会继续执行；报告上传和环境清理使用 `if: always()`，因此失败证据仍会保留。

`uc03-browser-e2e` 独立启动单体后端和测试基础设施，导入固定数据，只执行 5 项 UC-03 Playwright 用例。前端构建、浏览器安装或任一页面断言失败时，该作业失败，并保留 Playwright HTML、JUnit、失败截图、录像、trace 和后端日志。
