## 2. 测试目标与范围

### 2.1 测试目标

1. 验证直播间创建、查询、关闭等核心业务流程。
2. 验证弹幕和点赞的校验、持久化及 WebSocket 广播。
3. 验证前端直播间页面的异常回退、清晰度切换、登录提示和互动失败提示。
4. 验证 SRS 推流后的 HTTP-FLV 可用性及浏览器实际播放。
5. 确认代码提交后能够自动完成构建、测试和检查。

### 2.2 测试范围

| 范围 | 包含内容 |

## 6. 缺陷记录与修复

### BUG-001：SRS 浏览器测试持续失败

- **现象**：SRS 用例在 CI 中失败，重试后仍失败；失败发生在测试启动 FFmpeg 后不久。
- **原因**：`frontend/demo/e2e/live-ui.spec.js` 使用 `spawn('ffmpeg', ...)` 推流，但 GitHub `ubuntu-latest` 不保证预装 FFmpeg。
- **修复**：在 `.github/workflows/ci.yml` 的 `browser-e2e` job 中增加：

  ```yaml
  sudo apt-get update && sudo apt-get install -y default-mysql-client ffmpeg
  ```

- **修复提交**：`6ca62fe ci: install ffmpeg for SRS browser test`
- **验证结果**：修复后的 Actions 运行 `33046008142` 中，浏览器 E2E 和 SRS 用例均通过。

## 8. 结论、风险与后续工作

### 8.1 结论

当前 `microservice` 版本已完成直播服务核心业务、弹幕/点赞互动、异常分支和非 SRS 浏览器回归。SRS 播放链路仍有自动化脚本，但本机缺少 FFmpeg，不能把历史 CI 成功记录当作当前版本的本地通过证据。

### 8.2 已知风险

- Kubernetes 部署、自动扩缩容和故障处理已有当前工作区证据；HPA 扩容与缩容原始样本位于 `evidence/hpa/20260903-031813/`。
- 单体与微服务 API 均已有三次重复性能结果，对照汇总位于 `benchmark-results/性能对照汇总-20260903.md`。
- SRS 播放测试依赖 Chrome、FFmpeg、Docker 和可用的 SRS；本机需先安装 FFmpeg。
- 测试使用固定测试用户和动态数据，不能替代生产数据隔离与权限审计。

### 8.3 建议后续工作

1. 在本机安装 FFmpeg，重新执行 SRS 浏览器专项并保存结果。
2. 答辩前复核 `evidence/hpa/20260903-031813/`，现场展示 1→3→1 副本变化。
3. 答辩时展示 `benchmark-results/性能对照汇总-20260903.md`，并说明测试结果受本机资源和当前数据规模限制。
