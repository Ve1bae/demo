## 4. 各类测试结果

### 4.1 单元测试

覆盖推荐服务、视频服务、直播服务、控制器参数校验及异常分支。所有断言通过，验证了关键方法、业务规则和异常分支。

### 4.2 集成/API/WebSocket 测试

执行命令为后端 Maven 全量测试并启用 `RUN_UC03_API_TESTS=true`。

结果：119 项通过，其中包含 UC03 推荐 API、UC04 播放、UC05 评论、UC06 弹幕、UC07 创建直播间、UC08-10 直播 API 与 WebSocket 业务流。

### 4.3 HTTP 端到端测试

使用真实运行中的后端、MySQL、MinIO 和 SRS：

- UC04：获取视频详情、播放计数。
- UC05：提交评论并重新查询评论列表。
- UC06：提交弹幕并按时间区间查询。
- UC07：创建、查询、列表展示、关闭直播间，以及非法标题和未登录异常流程。

结果：UC04-06 通过；UC07 `6/6` 通过。

### 4.4 浏览器端到端测试

Playwright 共发现 16 项：11 项通过、3 项失败、1 项 flaky、1 项跳过。`flaky` 场景首次失败、重试通过，按测试质量要求仍需修复。

失败项如下：

1. **UC03 游客打开首页时按热度展示公开视频**
   - 期望：`8000 观看`。
   - 实际：`8001 观看`。
   - 原因：前置 UC04 HTTP E2E 已对同一 fixture 视频调用播放接口，导致数据被污染。
   - 已修复流水线顺序：浏览器 fixture 现在在 HTTP E2E 完成后重新导入；重新导入 fixture 后单独复跑该场景，结果为 `1 passed`。

2. **UC04 播放器加载视频详情并请求播放计数**
   - 播放地址为测试用的不可访问地址，浏览器媒体加载失败，播放按钮状态未按预期出现，最终等待播放请求超时。

3. **UC05 登录用户提交评论后页面显示评论**
   - 后端 HTTP 接口已写入评论，但页面端断言未观察到新增评论，需要检查前端提交后的列表刷新时序或测试等待条件。

4. **UC07 主播通过页面创建直播间并看到推流信息**
   - 首次运行未找到弹窗，重试后通过，属于 flaky，不应视为稳定通过。

5. **SRS 推流后直播间能播放**
   - 配置要求 `RUN_SRS_E2E=true`，本次未启用，按设计跳过；它是需要真实推流器参与的专项场景。

## 5. 前端构建结果

`npm ci` 和 `npm run build` 均通过。构建产物正常生成。npm 报告存在 4 个 high severity 依赖审计项，未影响本次构建和测试执行，后续应单独处理依赖升级。

## 6. 流水线改动

已调整 `.github/workflows/ci.yml`：

- 使用 `bash ./mvnw` 规避 GitHub Runner 上 wrapper 执行权限差异。
- 后端 Maven 测试在浏览器 fixture 导入前执行，避免 UC03 API 测试被 fixture 污染。
- HTTP E2E 完成后重新导入浏览器 fixture，避免播放计数和互动数据污染浏览器断言。

## 7. 最终判定

当前后端和 HTTP E2E 质量达到要求，但浏览器 E2E 仍有 3 个稳定失败项和 1 个 flaky 项。因此应先修复 UC04 播放媒体 fixture、UC05 页面刷新断言以及 UC07 弹窗时序，再重新执行完整测试并通过后进入镜像构建和 Kubernetes 部署阶段。
