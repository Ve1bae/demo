### 4.4 浏览器端到端测试

Playwright 共发现 16 项：11 项通过、3 项失败、1 项 flaky、1 项跳过。`flaky` 场景首次失败、重试通过，按测试质量要求仍需修复。

失败项如下：

1. **UC03 游客打开首页时按热度展示公开视频**
   - 期望：`8000 观看`。
   - 实际：`8001 观看`。
   - 原因：前置 UC04 HTTP E2E 已对同一 fixture 视频调用播放接口，导致数据被污染。
   - 已修复流水线顺序：浏览器 fixture 现在在 HTTP E2E 完成后重新导入；重新导入 fixture 后单独复跑该场景，结果为 `1 passed`。
2. **UC04 播放器加载视频详情并请求播放计数**
   - 播放地址为测试用的不可访问地址，浏览器媒体加载失败，播放按钮状态未按预期出现，最终等待播放请求超时。
3. **UC05 登录用户提交评论后页面显示评论**
   - 后端 HTTP 接口已写入评论，但页面端断言未观察到新增评论，需要检查前端提交后的列表刷新时序或测试等待条件。
4. **UC07 主播通过页面创建直播间并看到推流信息**
   - 首次运行未找到弹窗，重试后通过，属于 flaky，不应视为稳定通过。

## 6. 用例预计输出对照

本节补充每个用例执行完成后应观察到的结果。除特别注明外，API/HTTP 用例均要求 HTTP 状态为 `200`，业务失败场景要求响应体 `code` 与错误信息同时符合预期；单元用例要求断言通过且无未处理异常。

### 6.1 UC01-02、UC03-06 用例输出

| 用例范围 | 预计输出 |
|---|---|
| TC-01-1 | 返回 `code=200` 和保存后视频对象；标题、状态 `public`、默认清晰度 `720P`、播放地址及视频编号非空。 |
| TC-01-2 至 TC-01-3 | 返回 `code=400`；分别提示“视频标题不能为空”和“请选择要上传的视频文件”；数据库不新增记录。 |
| TC-01-4 至 TC-01-5 | 返回 `code=500` 且包含“视频上传失败”；数据库不新增不完整视频记录，临时文件被清理。 |
