# 视频服务微服务整合说明

## 1. 整合结论

当前工程采用“前端统一入口 + 后端职责分离”的整合方式，不把三个后端服务合并成一个进程。

- `user-service`：负责用户登录、注册、个人资料、关注、粉丝和兴趣标签。
- `live-service`：负责直播间、SRS 推拉流地址、直播弹幕、WebSocket 和直播点赞。
- `backend`：保留改造前单体代码目录，当前微服务 Compose 启动链路不依赖它；单体性能基线使用独立 Compose 文件和固定测试数据，不与微服务运行环境抢占端口。
- `video-service`：独立负责视频上传、MinIO 文件、点播播放、播放历史、清晰度、推荐、评论、点播弹幕、点赞和收藏。
- `frontend/demo`：包含 `VideoPlayer.vue` 播放器界面，是表现层，不属于后端微服务。

这与《video-service 微服务设计文档》和《3 个微服务的职责与边界划分》保持一致：视频数据不再由用户/直播服务维护，跨服务通过 HTTP 和网关路由协作。

## 2. 请求路由

| 前端请求 | 实际服务 | 说明 |
| --- | --- | --- |
| `/api/videos/**` | `video-service:8082` | 视频列表、推荐、详情、上传、播放、点赞、收藏、可见性 |
| `/api/comments/**` | `video-service:8082` | 评论点赞兼容接口 |
| `/api/videos/*/comments/**` | `video-service:8082` | 评论列表、发布、删除 |
| `/api/videos/*/danmakus/**` | `video-service:8082` | 点播弹幕 |
| `/api/minio/**` | `video-service:8082` | 对象存储接口 |
| `/api/user/**`、`/api/users/**` | `user-service:8081` | 用户、关注、兴趣、资料和推荐偏好 |
| `/api/live/**` | `live-service:8090` | 直播间和直播互动 |
| `/ws/live/**` | `live-service:8090` | 直播 WebSocket |
| `/video/**` | MinIO | 视频文件，保留 HTTP Range 支持拖动播放 |

## 3. 播放器与视频服务契约

`VideoPlayer.vue` 使用当前页面同源的 `/api` 入口。Compose 网关按路径将视频请求转发到 `video-service:8082`，因此开发环境和容器环境都不需要把 `localhost:9090` 写死。

视频详情或推荐结果中的 `sources` 字段提供清晰度到 URL 的映射，例如：

```json
{
  "720P": "/video/videos/example.mp4",
  "1080P": "/video/videos/qualities/example-1080P.mp4"
}
```

播放器使用以下后端能力：

- 播放时调用 `POST /api/videos/{videoId}/play`，由 video-service 增加播放量并记录历史；
- 清晰度切换使用 `sources`，不直接访问数据库；
- 弹幕使用 `GET/POST /api/videos/{videoId}/danmakus`；
- 评论使用 `/api/videos/{videoId}/comments`；
- 视频点赞、收藏和状态使用 video-service 的 `X-User-Id` 请求头；
- 视频文件访问保留 Range 请求，支持进度条拖动和断点读取。

## 4. 本地启动方式

### 开发模式

先启动：

推荐直接使用 `docker-compose.microservices.yml` 和 `scripts/start-microservices-local.ps1`，统一入口为网关 `8080`，视频服务内部端口为 `8082`，用户服务为 `8081`，直播服务为 `8090`，前端为 `5173`。

### Compose 联调模式

微服务 Compose 会启动三套独立 MySQL、MinIO、SRS、三个业务服务、网关和前端。网关转发：

- `/api/videos/`、`/api/comments/`、`/api/minio/` → `video-service:8082`；
- `/api/user/`、`/api/users/` → `user-service:8081`；
- `/api/live/`、`/ws/live/` → `live-service:8090`；
- `/video/` → MinIO。

## 5. UC-03 跨服务偏好

video-service 开启 `USER_SERVICE_ENABLED=true` 时，会通过：

```text
GET /api/users/{userId}/preferences
```

向用户服务读取关注作者和兴趣标签。用户服务不可用时，video-service 自动降级为热度推荐；观看历史由 video-service 自己的 `view_history` 表维护，不跨库读取。前端个人主页使用 `/api/users/{userId}/profile` 取得用户信息，再分别调用 video-service 的投稿和收藏接口取得视频数据。

## 6. 当前验证结果与边界

已完成真实 Compose 联调、三个服务测试、UC-03 浏览器回归、UC-04/05/06 HTTP 回归、UC-07 HTTP 回归、直播非 SRS 浏览器回归、Kubernetes 健康检查、故障降级和微服务 API 性能测试。证据分别位于 `evidence/compose-smoke/`、`evidence/k8s/`、`evidence/fault-drill/` 和 `benchmark-results/microservices/`。

仍需在答辩前补强或现场说明：当前本机没有 FFmpeg，SRS 推流浏览器用例不能在本机运行。单体与微服务性能已按同机同参数各重复 3 次完成，原始数据和对照汇总位于 `benchmark-results/`。HPA 已在 `evidence/hpa/20260903-031813/` 保存负载期间扩容和负载清理后缩容的原始输出。
